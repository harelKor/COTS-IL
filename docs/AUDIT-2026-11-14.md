# Site audit, Nov 14, 2026: speed first, then logic, UX and design

This audit covers the production site (https://cots-il.vercel.app) and the code at `c17ed8b`. Nothing in the code was changed.

Sources:
- `curl` timings from Israel.
- Lighthouse 12.8 runs: mobile (moto g power profile with 4× CPU throttling) and desktop.
- Vercel function and middleware metrics for Nov 9–14 and Vercel runtime errors.
- Three code reviews (performance, UX/design, logic/structure).

Every item below was checked in the code. Items marked *(unverified)* are inferred and still need a measurement.

## Why the site feels slow

There are three causes, in order of how much people feel them.

1. **On phones, the page never stops redrawing.**
   - Every card has `backdrop-filter: blur(24px)`, and product cards, vendor tiles and "גלו עוד" cards also run an endless "alive" bob animation.
   - The home photos repaint on every scroll frame (parallax variables on `<html>`, masks, filters, blend modes).
   - On a mid-range phone the main thread is busy for **8–9 s** on the home page and stores. That is mostly style, layout, paint and compositing work, not JavaScript. Desktop hides this.
2. **Server data is cached far less than it looks.**
   - Catalog reads use `"use cache"`. On Vercel that cache is **in memory, per server instance, per deploy** (Next 16.4 docs, `caching.md` "Shared store").
   - There were about **20 production deploys a day** this week (Nov 13: 19, Nov 14: 22). Every deploy and every new instance starts empty and goes to the database.
   - Uncached time to first byte (function p75, Nov 9–14):
     - home `1.2 s`, home prefetch segment `3.5 s`;
     - search API `1.1 s`;
     - info-page prefetches about `1 s`.
3. **Clicks wait for the server.**
   - Store pages, filtered catalog pages and product pages read the URL, so only their skeleton is prefetched. Each click is a server round trip (≈200–450 ms on desktop broadband, more on mobile and on cold instances).
   - The "+" buttons stay hidden until the header's per-request `Account` part arrives.
   - Each page change adds ≈350 ms of view-transition animation.

### What a user sees (screen recording, Nov 14, desktop Chrome, 1920 px)

The recording scrolls the home page. From about 5.7 s to 20 s, the "גלו עוד" cards show only their photos. Their titles, vendor names, prices and "+" stay blank, then appear all at once.

Nothing in the code hides that text (checked: no opacity gate or mounted flag in `family-card.tsx`). This is paint starvation: Chrome can't rasterize the text tiles. Each discovery card stacks:
- a `backdrop-filter` blur (`.glow-card`);
- an endless `alive` animation plus the `discover-in` entrance;
- a `card-shine` layer and a `mix-blend-multiply` photo;
- a masked scroll row (`scroll-fade-x`);
- all over a home photo that repaints on every scroll frame.

If a desktop stalls for 13 s, phones are worse. Fixing S-1 must make this recording's scroll show the card text immediately.

Other numbers:

- **Middleware (`proxy.ts`):** p75 12 ms, so `getClaims` verifies locally and is not the bottleneck.

- **Home page weight:** 311 KB HTML (29 KB brotli), of which 210 KB is the inline RSC payload; 74 `<img>` (70 lazy); 580 KB JS decoded (190 KB transferred); 97 KB CSS.

## Speed fixes, in priority order

### S-1. Stop the constant repainting (biggest win on phones)
- **Card blur:** remove `backdrop-filter` from `.card-surface`, `.glow-box`, `.glow-card` (`src/app/globals.css:1325,1341,1498,1525`). Their fill is already ~80% opaque, so the blur barely shows. Keep the blur on the header, sheets and the store flagship header.
- **"Alive" animations** (`globals.css:556-588`; `vendor-boxes.tsx:33`, `v/[vendor]/page.tsx:117`, `discovery-strip.tsx:189`):
  - run them only while on screen (an IntersectionObserver toggles a class) and not on touch devices;
  - or play them once on entry instead of `infinite`.
- **Home parallax** (`scroll-parallax.tsx:27-29`): it sets `--zoom`/`--drift` on `<html>` every frame, so the whole document restyles on each frame.
  - Set the variables on the photo element only, or use CSS `animation-timeline: view()`.
  - Turn it off under 1024 px.
- **Home photo effects:** bake the masks, colour grade and tint into the photo files instead of 6–7 CSS mask layers plus `filter`, `mix-blend-mode` overlays and a `blur(44px)` splash (`globals.css:1015-1064, 1125-1143`).
- **"גלו עוד" strip** (`discovery-strip.tsx:145`): it auto-scrolls every 4 s and fetches `/api/discover` pages even when it is off screen. Pause it with an IntersectionObserver.
- **Expected gain:** mobile TBT and main-thread time down by most of the "Other / Style & Layout / Rendering" share (≈5–6 s of the 8–9 s), and smooth scrolling. *(Exact gain unverified: re-run Lighthouse after the change.)*

### S-2. Make the cache survive deploys and instances
- Use `'use cache: remote'` for the hot shared reads in `src/lib/catalog.ts`:
  - `getFacets`, `getVendors`, `getVendorStore`, `getVendorPopular`, the discovery pool, `getFamily`;
  - category-only `searchCards`, `priceContext`/`getSettings`.
- Vercel provides the remote handler.
- Add `"use cache"` to `vendorSignals` (`catalog.ts:841-905`). It is a heavy CTE with no cache of its own and runs twice per store and once per vendor on the home page, in sequential loops. Run `getVendorStore`'s 3 queries with `Promise.all`.
- Batch deploys. Each push to `main` empties every cache, and doc-only or tiny visual commits each cost a cold site. Collect a session's commits and push once, or skip deploys for `docs/**` (Vercel "Ignored Build Step": `git diff --quiet HEAD^ HEAD -- . ':!docs'`).
- After each deploy, have a GitHub Action (or the existing `sync.yml` pattern) request `/`, `/catalog` and the four `/v/<code>` pages, so a person never pays for the cold render.

### S-3. Make clicks instant
- **Header `Account`** (`site-header.tsx:24-39`, `auth.ts:32-50`). Every signed-in request runs `getUser()` (HTTP to Supabase Auth), then the profile query, then the memberships query, then cart and checkout defaults, then `priceContext()`, all in sequence. Until this arrives, `mode === "loading"` and every "+" is hidden (`cart-store.ts:62,210`, `family-card.tsx:105`).
  - Use `getClaims()` and one joined query in `getViewer`.
  - Add `priceContext()` to the existing `Promise.all`.
  - On the client, start in `guest` mode when there is no `sb-*-auth-token` cookie, so guests get "+" immediately.
- **Store pages** (`v/[vendor]/page.tsx:256-261`): they await `params` and `searchParams` at the top, so the whole store renders per request.
  - Render the plain store front from `params` only.
  - Move filtered results into a lower Suspense branch.
  - Add `generateStaticParams` for the vendors and the most-viewed families.
- **Prefetch:** `prefetch={true}` on the few vendor-box and category-tile links; hover/touch-start prefetch on family cards (the docs advise against full prefetch on whole grids).
- **View transitions** (`globals.css:482-492`): shorten them to ≈120 ms with no 100 ms delay, and drop the `reveal` fade on streamed results.
- **Admin:** `admin-tabs.tsx:74` sets `prefetch={false}` and there is no `loading.tsx` anywhere, so admin tabs are blank until the server answers. Restore the default prefetch and add `src/app/admin/loading.tsx`.

### S-4. Lighter images
- **Home LCP on phones** (`home-scene.tsx:20`): `sizes: "... 250vw"` makes a 390 px phone download the 3000 px AVIF (381 KB). Cap it at ≈1500w (159 KB).
- **goBILDA/REV photos** are stored as `1280x1280` (`domain/bigcommerce.ts:200,354`). `src/lib/images.ts` only resizes Shopify URLs, so 48–240 px tiles load full-size originals.
  - Rewrite the BigCommerce `/stencil/{w}x{w}/` segment the same way.
- **Preconnect:** add `preconnect` for `cdn.shopify.com` and `cdn11.bigcommerce.com` in the root layout (there is none today).
- **Font:** the home motto's font, Heebo, is `preload: false` while `.motto` lists it first (`layout.tsx:21`, `globals.css:1204`). Preload it or put the system stack first.

### S-5. Faster server work per request
- **Add to cart** (`cart/actions.ts:77-85`) is `getViewer` (3 round trips), then variant select, then upsert, then `getCart`.
  - Use `getClaims` and one `INSERT … SELECT … RETURNING`.
  - BotID runs on every POST (`instrumentation-client.ts:9-14`) though only 4 actions check it. Scope it to those.
- **Catalog cache keys** (`catalog/page.tsx:51-59`): `sort`, `page` and `view` reach the facet functions, so sorting or paging re-runs 4–7 facet queries. Pass only the fields each function uses. Also:
  - use `count(*) OVER()` instead of a second count query;
  - run `supplierNames` beside the shape query.
- **Product query** (`catalog.ts:535`): `getFamily` selects `descriptionHtml` once per variant row. Select it per product.
- **Order pages** (`orders.ts:150-179`): `loadOrder` runs 5 queries in sequence; use `Promise.all`.
- **Missing index:** `audit_log` has no index for `(entity, entity_id, action, at)`, which every order page filters on (`orders.ts:260-287`).
- **Home `TeamNotice`** (`page.tsx:42`) loads the whole order list to show one row. Use `LIMIT 1`.
- **Search API** (`/api/search`, p75 1.1 s uncached): `quickSearch` can run twice in sequence, then suggestions. Check `EXPLAIN ANALYZE` on production for the trigram query (needs your OK for a production read).
- **DB idle timeout** (`db/index.ts:29`): 5 s means a quiet site opens a new pooler connection on most requests. Try 15–30 s and watch the billed duration.
- **`proxy.ts` matcher** (`proxy.ts:52`): it also runs for `/api/search` (every keystroke), `/api/catalog`, `/api/discover`, `.avif`, `manifest`, `robots`, `sitemap` and prefetches. Exclude them, and skip prefetches with `missing: [{ type: "header", key: "next-router-prefetch" }]`.

### S-6. Smaller client bundle
- `CartPill` mounts the 822-line `CartPanel` (sign-in, team setup) on every page, and `SearchPanel` loads eagerly. Load both on first open.
- Every `FamilyCard` subscribes to the whole cart store, so one add re-renders all cards. Select only that family's lines.

## Security and resilience notes
- Any email can claim any team number, and a `pending` team can already send requests (D11 by design). The first claimant blocks the real team. Consider admin approval before the first request, or a transfer tool.
- `/api/team-name`, `/api/search`, `/api/catalog`, `/api/discover` have no rate limit or `q` length cap, and `/api/team-name` reveals which numbers are registered. The Firewall rate-limit rule is already on the setup list (`docs/S9-OPS.md`).
- Approval links (`/q/<token>`) are 14-day bearer URLs. Send `Referrer-Policy: no-referrer` on `/q/*`.
- Exchange rate: there's no admin warning when the Bank of Israel rate is days old, and `createOrder` checks quantities but not the prices the team saw.
- Saving pricing or categories runs `regroupNow()` (≈10 s) inside the action, with no lock against the nightly sync's regroup. Add an advisory lock.
- A failed sync is only visible on `/admin/settings/system`. Email the admin (or send a Sentry event) when a sync job fails.

## UX and design

Overall the code is careful: no physical left/right classes, no text under 13px, toasts are live regions, and undo instead of confirm dialogs. The items below are mostly polish.

### Flows
- **Silent add to cart** (`cart-actions.ts:120-134`). Add-to-cart gives only a count change and a fly animation, with no announcement. Add a visually hidden `aria-live` line in `CartPill` ("נוסף לסל: …").
- **Orders list** (`orders/page.tsx:20-78`): no filter or paging. Add status chips (ממתין לאישור / בדרך / הסתיים) before a team has 40 orders.
- **Orders empty state** (`orders/page.tsx:28-34`): it is a dashed grey box, which the anti-slop rule forbids. Show a "pick a vendor" call to action instead.
- **Quote rejection** (`quote-decision.tsx`): "דחיית ההצעה" sits beside "בקשת שינוי", and its reason field autofocuses, popping the keyboard on phones. When the undo countdown ends, the button just vanishes; say "ההחלטה סופית".
- **Login** (`login/page.tsx:22-28`): the password path is hidden in a small `<details>`. Label it ("למנהלים") or remove it.
- **Pages built by hand** (`not-found.tsx`, `error.tsx`): their buttons and search field don't use `Button`/`fieldClass`, and the 404 input has no focus ring. The 404 also offers three actions where two would do.

### Visual
- **Product photo wells:** product cards use `bg-white` wells (`family-card.tsx:257,296,332`), while the product page uses `tile-fade`. Use one token.
- **Cart badge:** the cart count has a white ring (`cart-pill.tsx:31`) left from the light theme. Use the background colour.
- **Type sizes:** `text-sm` appears 156 times (login, team, invite, admin), outside the 13/15/17 scale. There are also arbitrary `text-[24px]`/`text-[28px]` sizes. Add a design-lint rule for these.
- **Cart sheet controls:** `cart-panel.tsx:29-30` re-creates button and field styles, and its address fields have no visible labels.
- **Alerts:** `Alert` info and danger differ only by colour. Add an icon.
- **Out-of-date doc:** CLAUDE.md still lists the light-theme status colours (#177A33 …) next to the dark ones.

### Accessibility and mobile
- **Cart sheet** (`cart-pill.tsx:97-104`): `aria-label` duplicates the visible heading (use `aria-labelledby`), and focus lands on the close button.
- **Search results** (`search-panel.tsx`): the listbox options contain nested buttons, which screen readers handle badly. Test with TalkBack or VoiceOver.
- **Repeated announcements** (`cart-panel.tsx:789`, `qty-stepper.tsx:56`): the live regions for the cart total and the stepper count re-announce on every tap.
- **Targets under 44px:** the account chip (`site-header.tsx:63`, `h-9`), the SKU copy chip (`family-view.tsx:291`, `h-8`) and the scroll arrows (`scroll-row.tsx:49`). Some may sit inside a larger tap area; check on a phone.
- **Phone checks still needed:** whether the Undo toast covers the cart pill at 360px, and whether the product page's buy bar takes too much height in landscape.

### Copy
- **One noun per stage:** בקשה (sent) → הצעה (quoted) → הזמנה (approved). Today the orders page calls a request "הזמנה" and the cart says "בקשה להצעת מחיר".
- **"ביטול":** it means undo an approval, cancel a sent order, and close a dialog. Be specific: "ביטול האישור", "ביטול השליחה".

## Structure

- **Data access versus the docs.** `src/db/index.ts` and CLAUDE.md say user reads go through the Supabase client with RLS, but 47 files read through the `db` pool. Permissions really live in `lib/auth` and `getOrderForViewer`. Fix the docs, or add a `forViewer()` layer with a test that list queries filter by team.
- **Two Postgres drivers.** Scripts (sync, regroup, seed) still use postgres.js, the driver that caused the Nov 10 hangs, against production. Move them to `pg` and remove `postgres`.
- **Large files:**
  - `lib/catalog.ts` (1,059 lines): split it into search, facets, stores and cards.
  - `cart-panel.tsx` (822 lines): move out the delivery form and the line list.
  - Also large: `admin/order-panel.tsx` (560), `search-panel.tsx` (539), `family-view.tsx` (516).
- **Legacy columns:** drop `memberships.role`, `team_invitations.role` and `team_role` (S0 step 7b).
- **Missing tests:**
  - `safeNext` with `\t`, `\n`, `\\` and encoded slashes;
  - integration tests for send, double send, approve and undo, and the fixed-price path;
  - no tests yet for `domain/content.ts` and `search-synonyms.ts`.
- **Docs drift:** `IMPROVEMENT-PLAN.md` (lines 26, 219, 222, 283) and `domain/reports.ts` still talk about prices including VAT.
