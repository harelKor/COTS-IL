# COTS-IL — UX, Design & Logic Audit

Nov 14, 2026 · @Harel

## Executive summary

COTS-IL has a strong core (cross-vendor catalog, Hebrew+English search, a full quote → purchase → warehouse → delivery pipeline), but it is not launch-ready: wrong supplier SKUs on merged products, a public pricing promise that contradicts the 1.6× markup, no outbound email, and empty business/contact details would each break trust or an order on day one.

**Top 8 issues (fix first):**

1. **Wrong SKU on multi-vendor products.** Kraken X60 shows `WCP-0940` even when CTR Electronics is the selected supplier, and live order #1008 (CTR) carries `WCP-0940`. Purchasing would order the wrong part number.
2. **Pricing contradiction.** Home trust strip says "מחיר הספק בש״ח, בלי תוספת" (no surcharge) while every other page says price = supplier USD × rate × 1.6.
3. **Email is not configured** (Admin → מערכת: `RESEND_API_KEY`/`EMAIL_FROM` missing). Teams get no quote, approval or delivery notifications.
4. **Business details are empty** (Admin → פרטי העסק). Result: /contact has a "דרכי קשר" heading with nothing under it, /returns says "כתבו לנו" with no way to write, footer has no name/phone, supplier lead times are blank.
5. **Product counts disagree everywhere:** hero "4,500+", catalog 4,360, admin sync 7,162; AndyMark and WCP both show exactly 1,169; admin category list shows 0 products for all 16 categories.
6. **Family/vendor merging is wrong or inconsistent:** "Timing Belt (HTD 5mm)" and "Aluminum Spur Gear (20 DP)" are attributed to "WCP, CTR Electronics"; Kraken Wire Bundle and NEO 550 appear twice; AndyMark's SDS swerve modules list as \~30 separate products instead of one family.
7. **Order status language is inconsistent:** the same state is called מוכנה למסירה / מוכנה לאיסוף / ממתינה למסירה / בהכנה on four screens, and the shipment says "בדרך" after it was received.
8. **Stale marketing copy:** /about and /how-it-works list 4 vendors (AndyMark, WCP, CTRE, TTB); the site has 7.

**How to use this doc (for the implementing session):** each finding has an ID (C-xx customer, A-xx admin, L-xx logic/data, D-xx design/a11y), the evidence seen on the live site on 14/11/2026, and a fix. The last section turns them into a prioritized plan with acceptance criteria — execute it in order P0 → P3, and re-verify each acceptance criterion on the deployed site. Not tested: the logged-in **team** flow (submitting a request, approving a quote, team account page) because no team login was available, and true phone-width rendering (browser could not be resized); both are listed as test tasks in the plan.

## Logic, data and security issues

The biggest risk is data identity: a merged "family" does not reliably carry which vendor and vendor SKU a line belongs to, and that flows straight into purchasing.

| ID | Severity | Issue | Evidence | Fix |
| --- | --- | --- | --- | --- |
| L-01 | Critical | Offer identity lost in merged products | Kraken X60 page `?v=WCP-0940` with CTR selected; order #1008 line "CTR Electronics, WCP-0940" sent to supplier order #5005 (CTR). | Model: `family → product (manufacturer part) → offer (vendor, vendor_sku, price, stock, url)`. Cart, quote and supplier-order lines reference `offer_id`. Migration: re-resolve existing lines; add a DB check that `line.vendor = offer.vendor`. |

## Benchmark vs WCP and Amazon

COTS-IL already beats WCP on cross-vendor search and Hebrew; it trails both on trust signals, delivery promises, bulk ordering and post-purchase communication. WCP's Kraken X60 page ([wcproducts.com/products/wcp-0940](https://wcproducts.com/products/wcp-0940)) lists $217.99, which matches COTS-IL's ₪1,116 (217.99 × 3.199 × 1.6).
